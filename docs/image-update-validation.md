Validated on 2 October 2026 using a locally packed, unpublished `PinguApps.Aspire.Hosting.Railway` 1.0.1 package, Aspire 13.6.0, and the existing dedicated [Core Integration allocation](https://railway.com/project/c702abd1-b897-4c2d-a7d9-3468fad4271a). Final consumers and isolated package caches were outside the repository at `V:/pin646-core-image-update-consumer-v3` and `V:/pin646-core-image-update-consumer-v4`.

The 1.0.0 sequence committed configuration with `skipDeploys: true` then called `serviceInstanceDeployV2`. In the integrated template test, Railway configured the new source but launched the previous image. A trial of `serviceInstanceDeploy(latestCommit: true)` also launched the previous web image during a live update; the new digest guard rejected it. A plain identical configuration patch can also be accepted without creating a deployment. The final correction commits the complete source/settings/runtime-variable patch with deployments enabled and a unique nonsecret request marker persisted before the request, then tracks its one exact scoped deployment. No additional redeploy is issued for that patch.

The finite job reported `SUCCESS`, stopped, and `EXITED` before the dependent web step ran. The [public web endpoint](https://image-update-web-proof-production.up.railway.app) returned HTTP 200; the web service remains running for inspection.

A fresh-state B deployment, representing a new CI checkout, also passed all 11 steps with identical desired configuration and a sealed runtime variable. It preserved web deployment `65574dcb-90d7-47c0-a9a9-cdefec53e97e` and intentionally ran the finite job again as `7a025a54-cbcc-4257-8d24-f0adb35aaae0`, with the same requested B digest, stopped state, and `EXITED` instance. The persisted request marker makes this intentional execution a real configuration change even when image and sealed inputs are unchanged.

A separate scoped provider probe first configured a new source with skipped deployment, then committed that identical source with deployments enabled. Railway launched the configured image in that public-image probe. The integrated private-image/sealed-variable case subsequently demonstrated that an identical patch can instead produce no deployment; the final marker avoids relying on that provider behavior.
